## 2. 环境构建与依赖安装策略 (uv 标准范式)

ClipLens 采用 **极简 `pyproject.toml` + 快捷 `uv pip` 补充** 的分层依赖安装策略：

1. **项目配置文件 (`pyproject.toml`)**：仅声明标准 PyPI 通用依赖，配置清华源（`tuna`），保持结构极简，避免复杂/冲突的 `sources` 重定向逻辑。
2. **GPU 版 PyTorch**：使用 `uv pip install -f <aliyun_wheels_url>` 指定阿里云/PyTorch 官方的 CUDA wheels 目录（`-f` 模式），精准获取 GPU 版本的 `torch` / `torchvision`。
3. **多模态模型 (`cn-clip`)**：使用 `uv pip install cn-clip` 进行快速装载。

### 标准三步安装指令：

```bash
# 步骤 1：同步基础环境依赖（使用清华 PyPI 镜像，极其迅速）
uv sync

# 步骤 2：安装带有 CUDA 硬件加速的 PyTorch 与 cn-clip 依赖
uv pip install torch torchvision -f https://mirrors.aliyun.com/pytorch-wheels/cu124/
uv pip install cn-clip

# 步骤 3：初始化环境，校验 GPU (CUDA) 并自动下载推荐模型权重
uv run python init_env.py
```

## 4.5 模型选型与硬件推荐分析 (RTX 4060 Ti 16GB)

针对 NVIDIA GeForce RTX 4060 Ti (16GB 显存) 硬件环境，对 Chinese-CLIP 官方提供的 5 款开源模型进行对比评估：

| 模型名称 | 显存占用 (FP16/FP32) | 分辨率 | 图文检索 Recall@1 | 综合推荐等级 |
| :--- | :--- | :--- | :--- | :--- |
| **Chinese-CLIP ViT-L/14@336px** | **~2.8 GB ~ 4.2 GB** | **336×336** | **高 (最强图文细节粒度)** | 🌟 **首选推荐 (最佳体验)** |
| Chinese-CLIP ViT-L/14 | ~2.5 GB ~ 3.8 GB | 224×224 | 中高 | 🥈 备选 (速度略快) |
| Chinese-CLIP ViT-H/14 | ~5.5 GB ~ 8.0 GB | 224×224 | 最高 | 🥉 可用 (推理耗时稍长) |
| Chinese-CLIP ViT-B/16 | ~1.2 GB ~ 2.0 GB | 224×224 | 中等 | 适用于轻量 CPU 场景 |
| Chinese-CLIP RN50 | ~0.8 GB ~ 1.5 GB | 224×224 | 较低 | 不推荐 |

### 选型推荐结论：`ViT-L-14-336` (ViT-L/14@336px)

1. **显存完全无压力**：4060 Ti 拥有 16GB 大显存，而 `ViT-L/14@336px` 运行时显存占用仅在 **3GB~4GB** 左右，即使并行后台扫描 + 前端高频检索，显存利用率依然非常轻松健康。
2. **分辨率优势显著 (336×336)**：相较于 224×224 模型，336px 高分辨率输入能够捕捉图像中**更小、更精细的物体与文字细节**（例如图片角落的物件、招牌上的文字描述），极大提升自然语言搜索本地相册的准确度。
3. **推理速度极快**：4060 Ti 的 Tensor Core 性能配合 FP16 混合精度推理，针对 `ViT-L-14-336` 可以实现 **150+ 张/秒** 的高吞吐量特征提取。

## 7. 升级与兼容

### 7.1 Schema 版本管理

- 全局库 `app.db` 与各项目 `metadata.db` 均在 `system_config` 表中维护 `schema_version` 键。
- **初始值**：`schema_version = 1`。
- **迁移时机**：应用启动、打开项目时检测版本；若数据库版本 < 当前代码期望版本，按序执行迁移脚本。

### 7.2 迁移策略

- 迁移脚本采用**增量、幂等**设计：`migrations/0001_init.sql`、`migrations/0002_add_status.sql` 等，每个脚本以"当前版本 + 1"为后缀命名。
- 执行流程：
  1. 读取当前 `schema_version`。
  2. 循环执行版本号大于当前的迁移脚本，每个脚本包在事务中。
  3. 每个脚本成功执行后将 `schema_version` 更新为对应版本。
  4. 脚本失败则回滚事务，保持原版本，应用提示"数据库升级失败"。

### 7.3 `system_config` 归属约定

- `schema_version`、`thumbnail_size` 等**项目级配置**存于各项目 `metadata.db` 的 `system_config` 表。
- 全局库 `app.db` 同样有 `system_config` 表，存放 `app_schema_version` 等全局配置。
- 两处 `system_config` 结构相同（`key` / `value`）。

### 7.4 兼容保证

- 保持图片路径不变原则，升级不影响原图。
- 迁移仅增补字段/索引，不做破坏性变更，保证旧数据可读。
- 缩略图/向量库升级失败可触发重建索引，不阻塞图片浏览。

## 8. 备份与恢复

- **备份**：拷贝项目 `.cliplens/` 目录即可备份元数据、向量与缩略图。
- **恢复**：拷回目录后在 ClipLens 中重新打开项目。
- **原图备份**：原图由用户自行管理，ClipLens 不迁移图片。
